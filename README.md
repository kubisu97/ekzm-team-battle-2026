# EKZM TEAM BATTLE 2026

2026年12月18日の忘年会で使う、スマートフォン向けのチーム対抗リアルタイムゲームです。
参加者は各自のスマホ（Wi-Fi共通でなくてOK）で参加・観戦し、司会者は管理画面から4ゲームを進行します。

| 用途 | URL |
|---|---|
| 参加者（QRコードの飛び先） | https://kubisu97.github.io/ekzm-team-battle-2026/ |
| 管理者（司会者） | https://kubisu97.github.io/ekzm-team-battle-2026/admin.html |
| リハーサル用テストツール | https://kubisu97.github.io/ekzm-team-battle-2026/test.html （管理者ログイン時のみ動作） |

## 構成

- フロントエンド：HTML / CSS / JavaScript（ビルド不要の ES Modules）
- 公開：GitHub Pages（main ブランチ / ルート）
- 同期：Firebase Realtime Database（Spark＝無料プラン）
- 認証：Firebase Authentication（参加者＝匿名、管理者＝メール/パスワード）
- Cloud Functions は使用していません（Spark プランでは使えないため）。進行・集計は管理者の端末で行い、書き込み権限はセキュリティルールで管理者UIDに限定しています。

## 当日の進行（司会者）

1. 管理者URLを開き、管理者アカウントでログイン（参加者用とは別タブ・別端末で可）。
2. 「📲 QR・設定」タブの QR を全画面表示 → 参加者に読み取ってもらう。
3. 参加者は名前とチーム（A〜E）を選んで参加。「👥 参加者」タブで人数を確認し、揃ったら「受付を締め切る」。
4. 「🎮 進行」タブで各ゲームを進行：
   1. 次のゲームを確認（必要なら変更）。各チームは参加者のスマホの「✋ わたしが出る！」で代表者を自分たちで決める。管理画面で全チーム「決定」になったら「代表者を発表する」
      - 欠席・通信トラブルでチームが決められないときだけ「緊急用：司会者が代わりに指定する」を使う
   2. 代表者が「準備OK」を押したら「ゲームスタート！」（3秒カウントダウン）
   3. クイズのみ：「第1問を出題」→「正解を発表」を3回繰り返す
   4. 「ゲーム終了・集計へ」→ 集計結果を確認（必要なら順位を手動修正）→「結果発表！」
   5. 「次のゲームへ」
5. 第4ゲームの結果発表後、「総合結果発表へ」で全員のスマホに最終順位と優勝チームを発表。

### トラブル時

| 状況 | 操作 |
|---|---|
| 代表者のスマホが途中で再読み込み・通信断 | 対戦中の画面で「再挑戦を許可」 |
| ゲームを最初からやり直したい | 集計画面または「QR・設定」の「このゲームをやり直す」 |
| 得点を直したい | 「🏆 得点」タブ →「G◯を修正」または調整点 |
| 間違ったチームで登録した人がいる | 「👥 参加者」で削除 → 本人が登録し直す |
| チームで代表者が決まらない・本人がいない | 進行タブの「緊急用：司会者が代わりに指定する」 |
| リハーサル後に本番状態へ戻す | 「QR・設定」→「全データ初期化」（クイズ問題は残る） |

## ゲームと得点

| # | ゲーム | 順位の決め方 |
|---|---|---|
| 1 | 10秒ぴったり | 10秒との誤差が小さい順（タイマーは最初の3秒だけ表示） |
| 2 | 早押しクイズ（4択×3問） | 正解数が多い順 → 同数なら正解した問題の合計回答時間が短い順。誤答・無回答は正解者より下位 |
| 3 | 居合斬りバトル | 「斬れ！」からタップまでの反応時間が短い順。「斬れ」前のタップと100ms未満はフライング＝失格 |
| 4 | 7秒連打バトル | タップ数が多い順。観戦画面は連打数をライブ表示（ラスト2秒は伏せ字） |

- 得点：1位100／2位70／3位50／4位30／5位10。第4ゲーム（最終）は2倍（管理画面で倍率変更可）。
- 同点：同じ記録は同順位・同得点、次の順位は人数分飛ばす（例：1位が2チーム→両方100点、次は3位50点）。
- フライング・記録なしは0点。管理者が手動で修正できます。
- 総合順位も同点は同順位。

## 公平性・セキュリティの設計

- 計測はすべて各端末内（`performance.now()` とタップイベントの時刻）で行い、通信遅延は記録に影響しません。開始の合図だけサーバー時刻で揃えます。
- 結果発表までは、観戦画面にも代表者本人にも正確な記録・順位を表示しません（他人の記録はルール上も読めません）。
- セキュリティルール（`database.rules.json`）：
  - 進行・代表者・得点・結果・設定は管理者UIDだけが書き込み可能
  - 参加者は自分の登録（1回のみ・チーム定員内）と、自分が代表のラウンドの自分の記録のみ送信可能
  - 代表者の立候補・辞退は、自分のチームについて自分自身だけ、しかも代表者発表前（待機中）のみ可能
  - 同じラウンド（同じ問題）の記録は1回しか書けない（二重送信・上書き不可）
  - 締切後・別ラウンドへの送信は不可
  - クイズの正解は管理者しか読めない（出題時は問題文と選択肢だけを配信）
- 本リポジトリは公開のため、ソースに含まれるサンプル問題は誰でも見られます。本番用の問題は管理画面で登録してください（DB内の問題は管理者のみ閲覧可）。

## 無料枠について（Firebase Spark プラン）

同時接続100、保存1GB、ダウンロード10GB/月。20〜25台の参加なら十分に収まります（1端末＝1接続、タブを複数開くとその分増えます）。

## 開発者向け：ローカル試験

```bash
node --test tests/*.test.mjs            # 得点ロジックとセキュリティルールの単体試験
node tests/mock-server.mjs . 8080       # モックサーバー（Firebase の代わり）
node tests/e2e.cjs                      # Playwright で管理者1+参加者10の4ゲーム通し試験
node tests/e2e-edge.cjs                 # フライング・再挑戦・やり直し等の例外系
```

`?mock` を付けて localhost で開くとモックサーバーに接続します（本番では無効）。モックの管理者パスワードは `mock` です。
